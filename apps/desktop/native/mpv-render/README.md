# wicaby_mpv (Linux only)

Node-API addon for the native Wayland "texture" mode. It runs libmpv in the main process, renders each frame into a ring of six GBM dmabufs (ABGR8888, through EGL/GLES 3), and hands their fds to JS so Electron's `sharedTexture` can draw them under the OSD. The JS contract is `src/main/playback/libmpv-native.ts`. The threading model is described in `src/player.h` and `src/renderer.h`.

- libmpv is loaded with `dlopen("libmpv.so.2")`, or the path in `WICABY_LIBMPV` when set (NixOS, a self-built mpv), and needs client API 2.1 (mpv 0.36) or newer; `libmpv.so.1` (API 1.x, mpv 0.34 and older) is never tried. Only the vendored ISC headers in `include/mpv/` are used, so libmpv is never a `NEEDED` entry. The addon links EGL, GLESv2 and gbm (`libgbm-dev libegl-dev libgles-dev` to build).
- Electron links its own FFmpeg (`libffmpeg.so`) into the global symbol scope. `src/ffmpeg_rebind.cc` points the system FFmpeg that libmpv loads back at itself (see the header for why `RTLD_DEEPBIND` is not used). If it cannot, `probe()` fails and the app falls back to detached mpv.
- `probe(renderNode?)` also checks the render node the way a player would (open it, GBM device, EGL display, GLES 3 context, then free it all) and returns `render: { ok, node, error? }`. The node is `renderNode`, else `WICABY_RENDER_NODE`, else the first `/dev/dri/renderD*` (sorted) that passes; `create(onEvent)` without a node uses the same one.
- The EGL display is always the GBM platform display of the render node. There is no surfaceless or default-display fallback: it can land on another GPU than the buffers, so the player fails instead and the app uses mpv's own window.
- Buffer allocation (`AllocRing`): the display's renderable (not external-only) ABGR8888 modifiers come from `eglQueryDmaBufModifiersEXT`. Each ring tries `gbm_bo_create_with_modifiers` with LINEAR alone first (every importer takes it, also another GPU), then with the whole list, then plain `gbm_bo_create`. A path is used only if every slot is single-plane, imports as an EGLImage and makes a complete framebuffer; NVIDIA, which cannot render to LINEAR, falls through to its tiled modifiers. Paths that failed that test are not tried again on resizes. Plain `gbm_bo_create` is the last resort because on AMD (radeonsi) it reports `DRM_FORMAT_MOD_INVALID`, which Chromium's GPU process fails to import (it restarts, and after three crashes Chromium drops to software compositing). `_with_modifiers2` is not used, to keep the libgbm floor at Mesa 17.1.
- Diagnostics reach JS as `log` events with prefix `wicaby-render-info` and level `info`: once at setup the GPU sync method (`EGL_ANDROID_native_fence_sync` or `glFinish`) and the modifier count, then once per ring the allocation path, modifier (hex), stride and size (flagged when the modifier is INVALID). Prefix `wicaby-render` (level `warn`) stays reserved for warnings JS acts on (a failed resize).
- When JS holds every slot, a new frame is rendered into a 1x1 scratch framebuffer and its swap reported, so mpv's video thread never waits the 200 ms flip timeout; the frame stays pending and the newest picture is drawn into the first slot JS releases.
- `probeNextFrame()` is an end-to-end picture check: the next frame rendered into a slot (a redraw is forced, so it also answers while paused) is read back after the GPU finished, and its `frame` event gains `probe`, a flat array `[x, y, r, g, b, ...]` for five points at fractions (0.5,0.5), (0.25,0.5), (0.75,0.5), (0.5,0.34), (0.5,0.66) of the ring size (`x = floor(fx * width)`, `y` counted from the top of the image as Chromium sees it). Other frame events have no `probe`.
- GPU driver fds (dmabufs, render node handles that NVIDIA's EGL/GBM opens without `O_CLOEXEC`) get `FD_CLOEXEC` after setup, each ring allocation and the first frame, so processes the main process spawns do not inherit the video buffers.
- On app exit, a player whose teardown hangs (a stuck libmpv core) is waited for at most 2 s, then left behind so the process can exit.
- When the render context is created, mpv logs `drmprime-overlay: Cannot retrieve DRM resources: Bad file descriptor` at error level. This is harmless: `DRM_DISPLAY_V2` carries only a render fd, which is all VAAPI interop needs.

Build: `node-gyp rebuild -C native/mpv-render` (from `apps/desktop`).

Test: `node native/mpv-render/test/smoke.cjs` (also runs `test/exit-hang.cjs`, the exit paths with a hung core), then `electron --ozone-platform=wayland native/mpv-render/test/electron-main.cjs` (with `ELECTRON_RUN_AS_NODE` unset). The tests are silent and use lavfi sources only.
